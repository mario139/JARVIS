Hablar con ollama:---------------
Ollama tiene una funcion llamada chat
Ya con ollama importada podemos hacer 
ollama.chat()-------Esta es la funcion para hablar con ollama dentro del programa
.chat() --- Tiene varios parametros importantes: 
ollama.chat(model= "", message = [{}]) -------- En el parametro model debes meter el nombre del modelo al que le quieres hablar. El parametro message lleva mas cosas: 
message = [{role = "user", content = ""}] ------ Se debe crear una lista con un diccionario dentro, lleva dos keys principales: role y content
Dentro de role, hay tres opciones, "user", "assistant" y "system" 
user: Le estas diciendo al programa que content va a llevar algo que ollama debe de responder, un mensaje del usuario para que ollama responda
assistant: Le estas diciendo a ollama que lo que va en content es algo que el asistente dijo previamente, sirve para guardar registro o historial de conversaciones
system: Indica que lo que va en content es un system prompt, personalidad, cosas que siempre siempre debe recordar el asistente (por ejemplo, si quiero que siempre me diga Mario, escribo un system prompt de que siempre me llame Mario )
Luego esta content, en content va el contenido, mensaje o prompt, es lo que ollama lee digamos, si quiero hacerle una pregunta, seleccino role user y en content pongo la pregunta.

Ejemplo-------------------------------

import ollama
from ollama import chat

response = ollama.chat(
    model="gemma3:12b",
    messages=[
        {"role": "user", "content": "Hola, ¿puedes presentarte en una frase?"}
    ]
)

print(response["message"]["content"])

-----------Tools / herramientas-----------------
Un agente no solo chatea: puede pedir herramientas (funciones de Python).
Ollama NO ejecuta el código. Solo pide: nombre de tool + arguments.
Nuestro programa ejecuta la función y le devuelve el resultado con role:"tool".
Luego Ollama genera la respuesta final en texto normal.

Flujo:
1. Usuario habla
2. ollama.chat(messages, tools=lista)
3. Si hay tool_calls → leer name y arguments
4. Ejecutar función Python (diccionario nombre→función)
5. Append mensaje del asistente + mensaje role tool
6. Segunda llamada a ollama.chat
7. Mostrar content final

Declarar tools (Herramientas.py):
- Lista de diccionarios formato Ollama
- parameters.type = object
- Cada parámetro va en properties
- required = lista de obligatorios
- description le dice al modelo cuándo usarla

arguments = valores que el modelo eligió (ej. {"ruta":"Notas.txt"})
herramienta(**arguments) los pasa a la función

Herramientas hechas:
- obtener_hora: sin parámetros, datetime
- leer_archivo(ruta): open + read; error en texto si falla
  No busca en todo el disco: solo la ruta que indiques (relativa al proyecto o absoluta)

Modelos:
- gemma3:12b NO soporta tools nativos
- qwen2.5:7b SÍ (el que usamos ahora)
- coder y llama3.1:8b guardados para después

Organización:
- tools/: funciones reales
- Herramientas.py: definiciones para Ollama
- agent.responder: coordina chat + tools
- main: solo input → historial → responder → print

Dudas aclaradas:
- Más tools casi no ralentizan; lo lento son 2 llamadas al modelo + historial largo
- Hora vieja: el modelo reusa el resultado anterior del historial en vez de volver a llamar la tool (pendiente opción C)
- filedialog posible después; primero ruta por parámetro (estilo agente)
- __init__.py = marca carpeta como paquete para imports

PARTE 3: SUBAGENTES
---------------------------------------------------------------------

Que es un subagente: otra llamada a ollama.chat con OTRO modelo y OTRO
system prompt. Se expone como una herramienta mas (delegar). No hace
falta ningun framework.

Flujo:
1. Le pido algo a Evee (el orquestador).
2. Evee decide que es programacion y llama a la herramienta delegar.
3. delegar manda la tarea al modelo programador (qwen2.5-coder:7b).
4. El programador responde y la respuesta vuelve a Evee.
5. Evee me la muestra.

OJO: el subagente NO ve el historial, solo la tarea que Evee le pase. Por
eso la descripcion de la herramienta pide incluir todo el contexto.

Archivos:

tools/subagentes.py
  - Diccionario SUBAGENTES: nombre -> {modelo, system prompt}.
  - Funcion delegar(agente, tarea) que hace la llamada al modelo
    correspondiente y devuelve el texto.
  - Para agregar otro especialista: una entrada nueva en SUBAGENTES y su
    nombre en el "enum" del esquema.

Herramientas.py
  - Esquema de "delegar" con agente (enum) y tarea.

agent.py
  - Import de delegar y entrada "delegar": delegar en HERRAMIENTAS.
  - Si la herramienta usada fue delegar, la respuesta se devuelve DIRECTA,
    sin que Evee la reescriba. Ahorra una llamada al modelo y evita que
    recorte o cambie el codigo.
  - (Respaldo opcional) regex PIDE_CODIGO: si el modelo no delega pero el
    mensaje suena a programacion, el codigo delega solo. Igual que ya se
    hacia con la hora.

Antes de usarlo: ollama pull qwen2.5-coder:7b
